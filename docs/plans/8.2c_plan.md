   ```bash
   mkdir -p ~/ocp-keys && chmod 700 ~/ocp-keys
   age-keygen -o ~/ocp-keys/ocp-offsite-ari.key        # prints "Public key: age1…"
   chmod 600 ~/ocp-keys/ocp-offsite-ari.key
   ```

## 5. What `offsite_backup.sh` does (in order)

`set -euo pipefail`, `umask 077`, every message starts with `offsite:`. Settings by env with
server defaults: `BACKUP_DIR=/root/backups`, `RCLONE_CONFIG=/root/.config/rclone/rclone.conf`,
`OFFSITE_REMOTE=ocp-offsite:ocp-backups/db`, `RECIPIENTS=/root/.config/ocp/age_recipients.txt`,
`OFFSITE_KEEP_DAYS=30`, `OFFSITE_MIN_KEEP=7`, `MAX_LOCAL_AGE_H=3`, `OFFSITE_PING_URL` (from
`offsite.env`; if unset, no ping, e.g. in tests).

1. **Guards** → stop with `offsite: FAILED step=check …` (and `/fail` ping):
   - recipients file exists and has exactly the `age1…` lines (2 expected, Q4); it does **not**
     contain `AGE-SECRET-KEY` (refuses to run if someone put a private key on the server);
   - `rclone.conf` is mode 600;
   - **A1:** a newest local `oil_change_*.sql.gz` exists, is **not empty** (size > 0) and is
     **younger than 3 h** (else `offsite: FAILED step=check newest dump is <N> h old / empty — did
     ocp-backup run?`). With the job at 03:20 and the backup at 03:00 a good night is ~20 min old.
2. **List remote once**: `rclone lsf --files-only "$OFFSITE_REMOTE"` → names already there.
3. (Order note: the freshness check guards *tonight's* backup. Older local dumps still go through
   the catch-up in step 4 even though they are older than 3 h; only their content is re-checked.)
4. **For every local dump not yet on OneDrive** (oldest first, catch-up, Q3):
   - re-check the dump (`gzip -t` + "dump complete" tail) — same test as backup.sh;
   - `age -R "$RECIPIENTS" -o "$tmp" "$dump"` into a temp dir (700) that a `trap` deletes;
   - check the result starts with the line `age-encryption.org/v1` and is bigger than 0;
   - `rclone copyto "$tmp" "$OFFSITE_REMOTE/<name>.sql.gz.age"` with `--config "$RCLONE_CONFIG"`,
     `-q --retries 3 --low-level-retries 10 --contimeout 30s --timeout 5m`. rclone compares size and
     hash after upload by default — **NEEDS VERIFICATION** that OneDrive's hash is used
     (`rclone backend features ocp-offsite:` lists `QuickXorHash`);
   - **A2: verify** with `rclone lsjson` on that one file → its `Size` must equal the local `.age`
     size in bytes (`stat -c %s`), else `offsite: FAILED step=verify remote <a> bytes, local <b>
     bytes` (and `/fail` ping). The file stays on OneDrive (a later run re-uploads it, because
     `copyto` replaces a file whose size differs), but the run counts as failed and nothing is pruned.
   Plain-text dumps are **never** passed to rclone; only `.age` files.
5. **Retention, only if every upload in this run succeeded:** from the remote list, take our own names
   (`oil_change_YYYY-MM-DD_HHMMSS.sql.gz.age`), read the date **from the name** (not from the remote
   modification time), delete those older than 30 days with `rclone deletefile`, but **always keep
   the newest 7** even if old (so a long outage never empties OneDrive). Other files in the folder
   are never touched.
6. **Log one line**: `offsite: OK uploaded 1 (oil_change_2026-11-07_030000, 21K) -> ocp-offsite:ocp-backups/db, 30 kept, 0 deleted`.
7. **Ping success** (`curl -fsS -m 10 --retry 3 "$OFFSITE_PING_URL"`). On any failure the `trap`
   sends `"$OFFSITE_PING_URL/fail"` and the script exits 1 with
   `offsite: FAILED step=<check|list|encrypt|upload|verify|prune> <short reason>`. A failed ping
   itself only adds a log line `offsite: WARNING ping failed` (the backup result does not change);
   a missing success ping makes healthchecks.io email Ari after the grace time anyway.
   The ping URL is never printed (curl runs with `-s`, the log says only "ping sent").

Never logged: the token, rclone's own debug output (`-v`/`-vv`/`--dump` are not used; `--dump
headers` would print the `Authorization: Bearer` line), file contents. rclone errors are shown only
as their last line, after a filter that drops anything with `token` or `Bearer` in it.

## 6. Timing and size

| UTC | Ulaanbaatar | What |
|---|---|---|
| 19:00 | 03:00 | `ocp-backup` makes the dump (takes seconds today) |
| **19:20** | **03:20** | **`ocp-offsite`** (new): encrypt + upload. `After=ocp-backup.service` makes it wait if the backup is still running at 19:20 |
| 19:30 | 03:30 | `ocp-messenger-cleanup` (small; overlap with offsite is harmless) |
| 00:00–04:00 | 08:00–12:00 | DigitalOcean Droplet Backup window. Our jobs are done ~4.5 h before it, so the DO snapshot already holds that night's local dump |

`Persistent=true` (Q3): if the server was off at 03:20, the job runs at boot. If the boot also
triggers the missed backup, `After=` makes offsite wait for it, so the newest dump is minutes old
and the 3 h check (A1) passes. If offsite still runs without a fresh dump, it fails with an alert,
and the next night's run uploads everything missed (catch-up).

**Size per dump: not measured yet.** Ari checks sizes only (no content):
`ls -lh /root/backups | tail -5`. Estimate until then (**ESTIMATE**, to be replaced by the real
number in the STEP 2 handoff): empty schema + destinations ≈ 10–50 KB gzipped; each service with
its reading/reminder rows adds roughly 100–300 bytes gzipped → a few hundred services a year keep a
dump **well under 1 MB**. age adds a ~200-byte header and 16 bytes per 64 KiB, i.e. nothing.
**30 copies on OneDrive ≈ 30 × (< 1 MB) < 30 MB**, under 1% of even the free 5 GB.

## 7. Failure: how Ari notices (Q1)

| Option | Catches failed run | Catches "never ran" / server gone | Work | Chosen |
|---|---|---|---|---|
| **healthchecks.io ping** (success / `/fail`; email on `/fail` or if no success ping in 24 h + 2 h) | yes | **yes** | 1 account, 1 URL | **chosen (Q1)** |
| Dashboard banner from a status file | yes | no | app code + UI | no |
| Email from the server (msmtp) | yes | no | SMTP password on server | no |
| Only `journalctl` | yes, if someone looks | no | none | no (nobody looks) |

The ping sends no data, only "ok" or "fail". Free plan size and terms: **NEEDS VERIFICATION**
on healthchecks.io/pricing before Ari signs up. On top: `journalctl -u ocp-offsite -n 20` always
shows the clear `offsite: OK` / `offsite: FAILED step=…` line.

**If OneDrive is down / token broken:** rclone retries, then the run fails → `/fail` ping → email.
Nothing is deleted (retention only after success). Local dumps keep 14 days, so the next good run
uploads every missed night (Q3). Outage > 14 days: the oldest missed nights exist only in DO's
7-day backups — acceptable, and the alert makes such a long outage unlikely to go unnoticed.
Token revoked (password change, "sign out everywhere", ~90 days without use — **NEEDS
VERIFICATION** of Microsoft's refresh-token rules): job fails every night until Ari repeats setup
steps 3 + 5 (`rclone config reconnect ocp-offsite:` also exists — **NEEDS VERIFICATION** that it
works headless with a pasted token).

## 8. Monthly restore test (Mac) — `scripts/offsite_restore_test.sh`

Ari runs it on the Mac, first week of every month (calendar reminder), and sends only the summary.

```bash
scripts/offsite_restore_test.sh --key ~/ocp-keys/ocp-offsite-ari.key              # newest via Mac rclone remote
scripts/offsite_restore_test.sh --key … ~/Downloads/oil_change_2026-11-07_030000.sql.gz.age   # or a file downloaded from onedrive.com
```

1. **Get the file:** a path given → use it; else `rclone lsf` + `rclone copyto` the newest from a
   Mac-side remote `ocp-offsite:` (Ari makes it once with `rclone config` on the Mac, browser
   login; a separate token from the server's). Download into `mktemp -d` (700).
2. **Refuse unsafe places:** the temp dir must not be inside `~/Library/CloudStorage` or any OneDrive
   folder (a decrypted dump there would be synced back to the cloud **in plain text**).
3. **Decrypt:** `age -d -i "$KEY" file.age > dump.sql.gz` → `gzip -t` + "dump complete" check.
4. **Throw-away Postgres:** `docker run -d --rm --name ocp-restore-<random> --tmpfs
   /var/lib/postgresql/data -e POSTGRES_PASSWORD=<random> postgres:16` (same major as prod; **no**
   `-p`, so no port is opened) → wait for `pg_isready` → `gunzip -c | docker exec -i … psql -X -q -v
   ON_ERROR_STOP=1`.
5. **Count:** rows per table in the dump (`dump_row_counts.awk`) vs `count(*)` in the container.
   Print **only** `table  in_dump  restored  OK/DIFFERENT`, plus the dump's date and its age in days.
6. **Clean up (trap, also on Ctrl+C / error):** `docker rm -f` the container (tmpfs → data gone),
   delete the temp dir (encrypted + decrypted files). Exit 0 = all tables match, 1 = otherwise.

Pass rule: exit 0 **and** the dump is ≤ 2 days old (proves the nightly upload works, not just an old
file). Result goes in the handoff / PROJECT_STATE by the PM.

## 10. Tests for CI (no network, no real secrets)

`tests/test_offsite.py`, same pattern as `tests/test_backup.py`: real bash script, fake `rclone`,
`age` and `curl` first on PATH that record their arguments in a temp dir and act on `FAKE_MODE`.
The fake `age` writes `age-encryption.org/v1` + the input reversed, so tests can tell encrypted
from plain. A fake `rclone.conf` with a dummy token string `FAKE-TOKEN-123` (no real format, so
gitleaks stays quiet).

| Test | Checks |
|---|---|
| upload happy path | one fresh dump → one `copyto` of a `.sql.gz.age` file whose content starts with the age header; log line `offsite: OK uploaded 1` |
| never uploads plain text | no rclone call ever gets a path ending `.sql.gz`; every uploaded file starts with the age header |
| catch-up | 3 local dumps, 1 already "remote" → exactly 2 uploads, oldest first |
| idempotent | second run with everything remote → 0 uploads, still OK |
| stale local backup (A1) | newest dump 4 h old → exit 1, `FAILED step=check`, `/fail` ping, no rclone upload; 2 h old → OK |
| empty local backup (A1) | newest dump 0 bytes → exit 1, `FAILED step=check`, `/fail` ping |
| no local backup | empty BACKUP_DIR → exit 1, `FAILED step=check` |

| bad rclone.conf mode | 644 → exit 1 |

## 11. Risks

| ID | Risk | Mitigation |
|---|---|---|
| R1 | rclone token on the server can read **and delete** the whole OneDrive | Backup-only account (Q2); 600 root-only; OneDrive recycle bin (C6); after each monthly test Ari keeps that tested `.age` file offline (USB) as an air-gapped copy |
| R2 | Backup account is a personal account → company loses access if Ari is not available | Recovery details + paper key stored together offline (§2); PM notes the account owner in PROJECT_STATE |
| R3 | **Private key lost → every off-site copy is useless** | Two recipients (Q4): Mac key (+ password manager) and offline paper key; monthly restore test proves the Mac key still works |
| R4 | Private key leaks | Never on server/OneDrive/git; script refuses `AGE-SECRET-KEY` on the server; paper key has no file copy |
| R5 | Token expires / revoked silently | Nightly use refreshes it; healthchecks alert; re-setup = steps 3 + 5 |
| R6 | Pinned rclone gets old (OneDrive API changes) | Upgrade on purpose: new pinned version + checksum in deploy.md (A3); a failure shows up at once via the alert |
