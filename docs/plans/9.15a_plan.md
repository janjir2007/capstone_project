## 4. Flow, step by step

1. **SMS goes out.** «Км шалгах» → «SMS илгээх» (today) uses the short text with the truck's ref link (§7).
2. **Driver taps the link** `m.me/<MESSENGER_PAGE_USERNAME>?ref=<ref>`.
   - Existing thread → `messaging_referrals` event with `ref`.
   - New thread → driver taps Get Started → `messaging_postbacks` event, ref inside `postback.referral`.
     ([m.me links](https://developers.facebook.com/docs/messenger-platform/discovery/m-me-links/))
   - Ref known → `messenger_links (psid, vehicle, 'ref', service_id)` + greeting:
     «Сайн байна уу! Машиныхаа улсын дугаар болон одоогийн км-ээ бичнэ үү. Жишээ: 9988НАА 871234»
   - Ref may never arrive ("might not work for some Messenger for Android customers", same page) → that is
     why the driver always types the plate (D-131, RISK-35).
3. **Driver writes.** Parser (`src/api/messenger/parse.py`, pure function):
   - Find **exactly one** plate: 4 digits not right after another digit, optional space/hyphen, 3 letters
     (Cyrillic or Latin look-alikes) → `normalize_plate` → must pass `is_valid_plate`.
   - Take the plate out. The rest, without spaces, commas, dots and «км/km», must be **one** number of 3–7
     digits. So «871234 9988НАА», «9988 НАА 871 234», «9988HAA, 871,234» all work.
   - No plate, no number, two numbers, anything else → **not a km message → no reply**. It stays in the
     Page inbox for a person (outline: non-km → human).
4. **Which truck** (P1):
   - "Ref truck" = the PSID's newest ref link **whose service is still that truck's latest service**
     (an old link from an earlier service does not count).
   - Typed plate in our DB → that truck. Ref truck exists and differs → mismatch.
   - Typed plate not in DB, ref truck exists → the ref truck, mismatch.
   - Typed plate not in DB, no ref truck → reply «Баярлалаа, манай ажилтан шалгаад холбогдоно.», nothing
     stored (a person sees the message in the inbox).
5. **Check before asking.** Run `new_reading()` (no save) with `reading_date` = UB date of the message's
   `timestamp` (P3). A 422 (no service, same day as the service) → the "ажилтан шалгана" reply, nothing stored.
6. **Ask.** Store `messenger_pending`, send «9988НАА — 871 234 км. Зөв үү?» with quick replies
   **«Тийм» / «Үгүй»**. A typed «тийм» / «үгүй» (any case) counts too.
7. **«Тийм»** (pending not expired):
   - `store_reading(source='messenger')` — same checks as manual. Mismatch → `status = flagged`,
     `flag_reason = plate_mismatch` (overrides an otherwise OK reading).
   - Link PSID to that truck (`'plate'`) if not linked. Delete pending.
8. **Reply** (inside the 24 h window, because the driver just wrote):
   - Usable: «Баярлалаа! 9988НАА өдөрт ~310 км явж байна. Дараагийн тос солих: ~2026.12.15 (883 234 км).»
     — numbers from the `pace` that the save returns.
   - Flagged (any reason): «Баярлалаа, хүлээж авлаа. Манай ажилтан шалгаад холбогдоно.» (never "wrong").
   - Mine truck (engine hours): thank-you, no date.
9. **«Үгүй»** → «Дахин бичнэ үү: улсын дугаар + км». Pending deleted. Expired pending + «Тийм» → «Дахин бичнэ
   үү…» (nothing stored).
10. **OTN opt-in** (only if `MESSENGER_OTN_ENABLED`): after a usable reading, send the OTN request
    «Тос солих өдрөөс өмнө сануулах уу?». The opt-in event → `messenger_otn` row.
11. **OTN send** (P2): «Сануулга» row shows «Messenger-ээр илгээх» when the truck has an unused, unexpired
    token. Tap → API sends the reminder text with the token → `reminders_sent (channel 'messenger')`,
    token `used_at` set. Otherwise the reminder goes by SMS as today (D-131).

## 5. Endpoints + contract v0.20 (additive)

| Endpoint | Public? | What |
|---|---|---|
| `GET /messenger/webhook?hub.mode&hub.verify_token&hub.challenge` | **yes** (Caddy) | Token matches `META_VERIFY_TOKEN` (constant-time compare) → 200 + challenge as text; else 403 |
| `POST /messenger/webhook` | **yes** (Caddy) | 1. raw body ≤ 64 KB · 2. `X-Hub-Signature-256` = `sha256=` + HMAC-SHA256(`META_APP_SECRET`, raw bytes), `hmac.compare_digest`; missing/wrong → 403, nothing parsed · 3. dedupe by `message.mid` (`INSERT … ON CONFLICT DO NOTHING`) · 4. flow (§4; a few DB queries) · 5. Send API call in a FastAPI `BackgroundTask` · 6. **200** |
| `POST /reminders/{service_id}/messenger` | no (internal) | P2 send. 201 = reminder row (`channel: messenger`) · 404 · 409 not latest service (same as `/sent`) · 422 not due / no token / OTN off · 502 `{code: "meta_error"}` — Meta refused, **no row stored**, token not used |
| `GET /reminders/due` | no | + `messenger_ready: bool` per reminder (unused, unexpired token; false when OTN off) |
| `DELETE /readings/{id}` | no | Also removes `source = messenger` readings («Буцаах», RISK-34); still refuses `service` |
| Reading | — | `source` may be `messenger`; `flag_reason` may be `plate_mismatch` |
| KmCheck `message_mn` | — | short text with the m.me link when `MESSENGER_ENABLED=true`; today's text when false |

- `MESSENGER_ENABLED=false` (default) → both webhook routes 404, SMS text unchanged. Safe to deploy before Meta is ready.
- **Caddy:** one new block before the catch-all, no `forward_auth`:
  ```
  handle /messenger/webhook {
      request_body { max_size 64KB }
      reverse_proxy api:8000
  }
  ```
  Every other API route stays inside the compose network. A test reads `deploy/Caddyfile` and checks that
  this is the only new public path.
- **Logs (P5):** Meta sends `hub.verify_token` in the query string, and uvicorn's access log prints query
  strings. A logging filter on `uvicorn.access` removes the query for `/messenger/webhook`. Our own logs:
  event type and result only — never PSID, body, token, or secret. A `caplog` test checks it.
- **New settings (server `.env` only, names in `.env.example` with empty values):**
  `MESSENGER_ENABLED`, `MESSENGER_OTN_ENABLED`, `META_APP_SECRET`, `META_VERIFY_TOKEN`,
  `META_PAGE_ACCESS_TOKEN`, `META_PAGE_ID`, `MESSENGER_PAGE_USERNAME` (placeholder until Ari gives it),
  `META_GRAPH_VERSION`. API refuses to start with `MESSENGER_ENABLED=true` and any of these empty.

## 7. Km-check SMS (P4, RISK-33)

Counted with the repo's `sms_parts()` (UCS-2: 70 one part, 67 per part when split → 2 parts = 134).

| Text | Chars | Parts |
|---|---|---|
| Today: «Сайн байна уу! 1234УБА машины тосыг 2026.10.01-нд солиулсан. Одоогийн км-ээ хариу бичнэ үү. Wolf Oil - Гео-Эксперт: 99112233» | 124 | 2 |
| **New (short, no date):** «Сайн байна уу! 1234УБА машины одоогийн км-ээ хариу бичнэ үү эсвэл m.me/geoexpertmn?ref=K7Q2M9XA Wolf Oil - Гео-Эксперт: 99112233» | 128 | **2** |

- Length = 117 + username length (7-char plate, 8-char ref, 8-digit phone). Stays 2 parts up to a
  **16-char username** (`GeoExpertWolfOil` → 133); 18 chars → 3 parts.
- The ref is 8 characters for this reason (10 would cost the margin).
- STEP 2 test: real-username worst case = 2 parts; API logs a warning at start if the configured
  username makes it 3.
- A truck known by a fleet number longer than 7 characters eats the margin the same way.
- Ari proofreads the Mongolian.

## 9. Tests

**Without Meta (pytest, runs in CI):**

  wrong, signed with another secret, body changed after signing → 403 and nothing stored; > 64 KB refused.
- Verify GET: right token → challenge; wrong → 403; `MESSENGER_ENABLED=false` → 404.
- Dedupe: same `mid` twice → one pending row, one reply.
- Parser table: «871234 9988НАА», «9988 НАА 871 234», «9988HAA, 871,234», «9988нАа 871234 км» → (plate,
  km); «сайн уу», «871234» alone, two plates, two numbers → None.
- Flow (fake sender records calls): ref → greeting; message → pending → «Тийм» → `messenger` reading,
  pace + reminder day move; mismatch with typed plate known → flagged on typed truck; typed plate unknown

  stored; reading date = message day even when «Тийм» is the next day; non-km → **zero** sender calls.

## 11. Risks

| Risk | Mitigation |
|---|---|
| A stranger sends fake km (the ref is not a password; anyone can type a real plate) | Confirm step; pace limits 20–1200 km/day; mismatch flagged; source «Messenger» visible on the card; «Буцаах» (RISK-34) |
| The only public path is the webhook; a wrong Caddy edit could open more | Signature check before anything; Caddyfile test; body limit 64 KB |
| Webhook disabled after 1 h of failures (e.g. long deploy or server down) | `docs/deploy.md`: check the webhook after each deploy, re-subscribe if disabled |
| Reply lost if the API restarts between the 200 and the background send (`mid` already marked) | Accepted: driver can write again; reading is already saved before the 200 |
| OTN is Beta and may disappear (Meta already removed tags in 2026) | Behind a flag; reminder by SMS stays (D-131); Utility Messages as a later option |
| App Review / Business Verification time unknown (RISK-32) | Deploy with flag off; dev-mode test; «Хариу бүртгэх» meanwhile |
| SMS goes to 3 parts with a long Page username or long fleet number (RISK-33) | 8-char ref; username ≤ 16; test + start-up warning |
| PSID is personal data on a Singapore server | Same accepted risk as phones (D-124); no profile data, no message text stored |
| Verify token seen in a log before the filter existed | Filter in 9.15a-2 + rotation step (§8.8) |
| Migration 011 also planned by 9.2 | §0.1 — first built takes 011 |
